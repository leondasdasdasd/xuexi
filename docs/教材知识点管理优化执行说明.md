## 2. 内容中台参考结论

### 2.1 教材管理结构

内容中台的教材管理在 `Content_Hub/src/App.jsx` 的 `activeTab === "教材管理"` 区域。

它的结构是：

- 教材册实体：`textbook`
- 教材册元数据：`systemType / stageId / stageName / subjectId / subjectName / edition / grade / volume / name / status`
- 教材目录：`textbook.nodes`
- 目录节点：`{ id, type, name, sort, knowledgeIds, children }`

左侧先按教材版本分组，再按年级分组，再列出册别。右侧展示当前教材册的目录树。

参考函数：

- `buildTextbookVersionGroups`
- `buildTextbookGradeGroups`
- `findTextbookNode`
- `mapTextbookNodes`
- `appendTextbookNode`
- `flattenTextbookNodesForOptions`
- `TextbookDirectoryRows`
- `TextbookNodeTree`

内容中台的真实语文教材 mock 在 `primaryChineseSeed.mjs`，结构是“教材册 -> 单元 -> 课文/课时”。可以抽取几册作为本项目前端 mock。

### 2.2 知识点管理结构

内容中台知识点管理只按范围筛选：

- `systemType`
- `stageId`
- `subjectId`
- 国际课程时才有 `curriculumId`

本次测验项目不需要国际课程体系，按“学段、学科”即可。

知识点节点结构：

- `id`
- `parentId`
- `stageId` 或当前项目里的 `stage`
- `subjectId`
- `name` 或当前项目里的 `text`
- `level`
- `sort`
- `status`
- `children`

参考函数：

- `scopedKnowledgeNodes`
- `filterKnowledgeTreeNodes`
- `ConfigKnowledgeTreeNode`
- `KnowledgeEntityModal`

### 2.3 知识点关联组件

内容中台的知识点打标组件在 `QuestionKnowledgePickerModal`。

关键能力：

- `flattenKnowledgeTree`
- `knowledgePathNodes`
- `knowledgePathLabel`
- `deepestKnowledgeIds`
- `primaryKnowledgeIdList`
- `normalizeKnowledgeSelectionPatch`
- 横向多级展开
- 搜索知识点名称和完整路径
- 已选知识点区域
- 主/次知识点标记
- 只保留最深层知识点，父子同时选中时只展示子级

本次应把这个交互模式迁到教材节点挂知识点里，而不是继续用普通下拉或简单树选择。

## 3. 当前测验项目现状

当前基础设置页在 `src/routes/Exam/basicSetting.js`。

已有行为：

- `activeTab == 0`：教材管理，原章节管理。
- `activeTab == 1`：知识点管理。
- 教材树接口：`/api/chapter/showAllChapter`
- 知识点树接口：`/api/knowledge/list`
- 教材版本接口：`/api/knowledge/getTeachingMaterial`
- 课程资源里另有前端枚举 `courseResourceVersionList()`。

当前问题：

- 教材筛选现在是“学段、学科、年级、版本”，用户希望改为“学段、学科、版本、册别”。
- `getTeachingMaterial` 只返回单个默认版本对象，不是完整版本列表。
- 课程资源的 `courseResourceVersionList()` 是前端固定版本枚举，但不是维护入口。
- 当前没有独立教材版本管理页面。
- 教材目录仍依赖 datagrid 表格，层级表达不够清晰。
- 当前教材关联知识点是普通 `treeSelect`，不支持内容中台式搜索、主次、横向展开。

## 4. 建议目标数据模型

### 4.1 前端教材册模型

先在前端建立 mock 数据，后续可替换为接口。

```js
const textbookBooks = [
  {
    id: "mock_rj_math_junior_7a",
    stage: 3,
    stageName: "初中",
    subjectId: 2,
    subjectName: "数学",
    versionId: 2,
    versionName: "人教版",
    gradeName: "七年级",
    volumeName: "上册",
    bookName: "七年级上册",
    catalog: [],
  },
];
```

字段说明：

- `versionId/versionName`：教材版本。
- `bookName`：用于筛选展示的册别，例如“七年级上册”。
- `gradeName/volumeName`：内部保存和后续接口对接用。
- `catalog`：当前册的目录树。

### 4.2 教材目录节点模型

```js
{
  id: 'unit_1',
  parentId: '',
  name: '第一章 有理数',
  nodeType: 'unit',
  sort: 1,
  knowledgeIds: [],
  primaryKnowledgeIds: [],
  children: [
    {
      id: 'chapter_1_1',
      parentId: 'unit_1',
      name: '正数和负数',
      nodeType: 'chapter',
      sort: 1,
      knowledgeIds: [],
      primaryKnowledgeIds: [],
      children: []
    }
  ]
}
```

节点类型只用于新增时推断、详情或接口字段，不再单独作为列表列展示。

默认层级建议：

- 第 1 层：单元 / 章
- 第 2 层：节 / 章节
- 第 3 层：课时 / 小节
- 第 4-7 层：子节点

界面上不强制显示“单元/章节/课时”列，主要靠树缩进、展开符号和节点名称表达。

### 4.3 知识点模型

保持当前接口字段兼容：

```js
{
  id: 1001,
  parentId: '',
  stage: 3,
  subjectId: 2,
  text: '数与代数',
  level: 1,
  children: []
}
```

展示时统一映射为：

```js
{
  id,
  parentId,
  name: text || name,
  level,
  children
}
```

界面显示只用 `name`，不拼“一级｜”前缀。

## 5. 具体改造步骤

### 5.1 梳理运行环境

进入测验项目后先执行：

```bash
nvm use
```

本地访问优先使用已有端口。如果重启，保持或重新确认 `http://127.0.0.1:8021/#/basicSetting` 可访问。

### 5.2 先抽基础数据工具

建议在 `basicSetting.js` 内先抽纯函数；如果文件变长明显，再拆到同目录 helper 文件。

需要的工具函数：

- `normalizeStageName`：把“小学段、初中段、高中段”展示成“小学、初中、高中”，并支持“幼儿园”。
- `getMockTextbookVersions`：返回可用教材版本，优先复用 `courseResourceVersionList()`。
- `buildMockTextbookBooks`：按学段、学科、版本生成册别。
- `getTextbookBookKey`：稳定识别当前教材册。
- `getCatalogForBook`：返回当前册独立目录。
- `findTreeNode`
- `mapTreeNodes`
- `appendTreeNode`
- `removeTreeNode`
- `getTreeDepth`
- `flattenKnowledgeTree`
- `knowledgePathLabel`
- `deepestKnowledgeIds`

新增纯函数必须补业务测试，重点测：

- 不同册别目录不同。
- 知识点只按学段学科过滤。
- 父子知识点同时选择时只保留最深层。
- 树深第 7 层不能继续新增。

### 5.3 改筛选区

教材管理筛选：

1. 学段
2. 学科
3. 教材版本
4. 册别

知识点管理筛选：

1. 学段
2. 学科

注意：

- 教材管理不再先选“年级”再选“版本”。
- 册别显示“七年级上册、七年级下册”等。
- 当前选中摘要也按这个顺序展示。
- 不要在教材目录表格里重复展示版本、年级、册别。

### 5.4 改教材目录展示

优先用当前项目现有风格实现树形目录，不必强行保留 datagrid。

建议结构：

- 顶部：当前教材册信息，例如“人教版 / 七年级上册”
- 左或主区域：教材目录树
- 操作：新增同级或新增下级、编辑、删除、保存
- 右侧或弹窗：知识点关联

如果继续用 `@yungu-fed/datagrid`，必须确保：

- 第一列只叫“教材目录”
- 不显示“类型”列
- 节点名称不带层级前缀
- 操作列第 1-6 层能新增子节点，第 7 层不能新增
- 新增未保存节点有临时 `id/key`，保存时不能误走更新接口

### 5.5 改知识点树展示

知识点管理只显示树：

- 第一列或树节点显示知识点名称。
- 层级通过缩进/展开表达。
- 不显示“一级｜名称”。
- 不按年级、版本、册别区分。
- 新增子节点同样最大 7 层。

### 5.6 做知识点关联组件

新增一个可复用组件，建议命名：

- `KnowledgePickerModal`
- 或放在 `src/routes/Exam/components/KnowledgePickerModal`

功能要求：

- 输入：`knowledgeTree`、`value`、`primaryValue`。
- 输出：`onApply(nextKnowledgeIds, nextPrimaryKnowledgeIds)`。
- 搜索：搜索知识点名称和路径。
- 多级横向展开：每一级一列或一行，点击父级展开下一级。
- 选择规则：默认只选择叶子节点；如果选择了父节点和子节点，保存时只保留最深子节点。
- 主次：已选知识点可以切换主/次，至少支持多个主知识点；如果只允许一个主知识点，要在文案和逻辑里明确。
- 显示：已选区只显示最子一级名称，tooltip/title 可显示完整路径。

教材目录节点挂载字段：

- `knowledgeIds`
- `primaryKnowledgeIds`

如果当前后端暂不支持 `primaryKnowledgeIds`，前端 mock 仍保留，保存接口先只提交 `knowledgeIdList/knowledgeIds`，并在测试报告里说明后续接口对接点。

### 5.7 保存与接口兼容

教材目录保存仍兼容当前接口：

- 新增：`basicSetting/addChapter`
- 更新：`basicSetting/updateChapter`
- 删除：`basicSetting/deleteChapterNoChildern`

提交字段注意：

- `name`：真实节点名，不带层级前缀。
- `stage`
- `subjectId`
- `gradeId`：由当前册别映射得到，不在列表展示。
- `sourceType`：由当前版本映射得到。
- `knowledgeIdList`：逗号字符串。
- `knowledgeIds`：数组。

知识点保存仍兼容当前接口：

- 新增：`basicSetting/addKnowledge`
- 更新：`basicSetting/editKnowledge`
- 删除：`basicSetting/deleteKnowledge`

提交字段注意：

- 不带 `gradeId`
- 不带 `sourceType`
- 不带 `teachingMaterialVersion`

### 5.8 样式与响应式

按云谷 B 端风格：

- 界面密度适中，适合反复维护。
- 树和关联组件要清楚、可扫描。
- 尽量使用 `rem/%/fr/minmax/clamp`。
- 不要出现卡片套卡片。
- 不要用大面积营销风 hero。
- 桌面、窄桌面、平板、手机宽度都要检查。

建议验证宽度：

- 1440
- 1140
- 768
- 390

检查：

- 筛选区是否换行合理。
- 树节点操作按钮是否可见。
- 知识点关联弹窗是否横向溢出。
- 英文或较长名称是否挤压按钮。
